# Receiving Code Review

Feedback gets TECHNICAL EVALUATION, not performative agreement. The
reviewer can be wrong; you are the one standing at the code.

1. **Read it fully** before responding to anything.
2. **Evaluate each finding:** correct / incorrect / matters-of-taste.
   For "incorrect": verify against the code, then say so WITH EVIDENCE
   - pushing back on a wrong finding is a deliverable, not defiance.
3. **Correct findings get fixed** with a test where sensible
   (`test-driven-development`).
4. **Ambiguous?** Reproduce or ask ONE precise question - never
   implement something you don't understand.

Blind implementation of every suggestion is as much a failure as
defending every line. The output is the best code, not agreement.
