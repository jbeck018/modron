# Review and bench round, 2026-11-23

Four read-only review passes (core engine; server, protocol, store and
bridge; tools, providers and CLI; app and client core) plus a first
modron-vs-omp run on terminal-bench (scripts/tb, "Agent comparison").
Findings were traced by reading the code path; the ones marked FIXED were
changed in this round and have tests. OPEN items are not started.

Severity: H = wrong result, lost work or an authorization gap a user can
hit; M = real but narrow, or needs an unusual setup; L = cosmetic or
hardening.

## Found by running the bench

| Id | Sev | Finding | Status |
|---|---|---|---|
| B1 | H | Headless runs (no delta sink: `modron "task"`, reviewer, escalation, compaction summary) used the blocking transport, which has a 120 s total deadline per request. A reasoning model that needs longer for one response timed out, was resent from the start (billed again) and could fail the run. Seen as 145 s, 179 s and 338 s turns and 40 requests for a 16-turn task. | FIXED: `turn_unobserved` in engine.rs sends every unobserved turn over the streaming transport (idle timeout only). |
| B2 | H | A response cut off by the output cap (8192 tokens, reasoning included) either failed the run ("malformed tool arguments") or ended it with an empty answer. glm-5.3 can spend the whole cap reasoning. | FIXED: the cut call is dropped (openai_compat.rs, anthropic.rs), the engine tells the model and continues, at most 3 times per run; never an empty assistant message. |
| B3 | H | The HTTP client trusted only the bundled Mozilla roots, so modron could not reach any provider behind a TLS-inspecting proxy or a private CA; the error was a bare "connection error". | FIXED: native roots (system store, SSL_CERT_FILE) are trusted as well (root Cargo.toml). The error text still hides the cause: OPEN. |
| B4 | M | A server that ignores `"stream": true` and answers with one JSON document failed the turn as a dropped connection. | FIXED: `json_instead_of_stream` in providers/http.rs. |
| B5 | M | `MAX_OUTPUT_TOKENS` is a constant 8192 for every model. Models with large output limits are capped far below what they can do, and reasoning eats into it. | OPEN: take the cap from the catalog (per model), keep 8192 as the fallback. |
| B6 | M | Trivial tasks cost 4 to 6 requests where omp uses 2 (write, read back, shell check, self-check). | OPEN: skip the read-back and the self-check turn when the run made one small write and the task named no checks. |
| B8 | M | cargo-deny failed on main: RUSTSEC-2026-0592 (`url` below 2.5.9, stack overflow in `Url::origin()`). | FIXED: `url` 2.5.9 in the root and app lock files. |
| B9 | H | The `interact` tool typed the word "Enter" instead of pressing the key (`tmux send-keys -l` makes every argument literal), so `enter: true` never submitted a line. Seen in the maze task: the model gave up on `interact` and wrote its own pty driver. | FIXED: the text and the key are two sends; `--` protects keys that start with a dash (interact.rs, with a tmux test). |
| B10 | M | The read-before-edit gate refused the first edit of a file the session itself had just written; each one cost a failed edit and a read turn (three times in one maze run). | FIXED: `write` marks the file as read (write.rs). |
| B11 | L | `plan` refused a call that carried `items` but no `op`. | FIXED: `op` is inferred from `items` (set) or `index` (update). |
| B12 | M | Turn overhead seen in the maze run (45 requests against omp's 14): 13 `plan` calls, several turns spent only correcting plan statuses; a mock server, a test harness and a 40-case fuzz test for a 5x5 maze; three turns for the end-of-run self-check, which also copied the result to a second path nobody asked for. | OPEN: prompt and finish-gate tuning; measure with scripts/tb/compare.sh. |
| B7 | L | A stream that dies after the first delta is not retried even when nobody is watching the deltas (headless). | OPEN: allow a replay when the caller discards deltas. |
